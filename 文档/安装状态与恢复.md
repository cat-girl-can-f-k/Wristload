# 安装状态与恢复

## 平台边界

| 平台 | RFCOMM | 真实安装 |
|---|---|---|
| Windows | 已接入 | 已接入，需真机 HCI 验证每个设备型号 |
| Android | 已接入，首次请求蓝牙权限 | 已接入，需 Android 真机验证 |
| Linux | 未实现 | 不支持，不会伪装为可安装 |

安装仅允许发生在用户已授权、且 authkey 会话已认证的 RFCOMM 链路中。GATT
连接成功不代表安装授权。

## 文件校验

- 表盘从原始文件或容器内 `resource.bin` 的固定头部读取数值型 `faceId`。用户可编辑，
  但空值、非数值和解析失败都拒绝安装。
- RPK 在内存中读取全部受限候选清单。包名必须从清单取得、格式有效且全包唯一，不能
  手填；多个清单的包名或有效版本互相冲突时直接拒绝。版本缺失时才让用户填写正整数版本号。
- 不创建解压目录、不复制源文件。元数据分析在后台 isolate 完成，避免大文件阻塞 UI。
- MD5 仅用于设备协议互操作；本地源文件一致性同时核对大小、MD5 与 SHA-256，避免把
  MD5 当作抗篡改校验。

## 传输与终态

控制命令使用 `channel=1 + WRITE_ENC`，Mass 文件使用 `channel=2 + WRITE`。
发送端按用户设置的 1–50 片窗口排队，并按 L1 累计 ACK 精确确认进度；
进度和速度只统计设备已确认的源文件字节，不把排队字节计入 KB/s。

取消、控制超时、ACK 超时、RFCOMM EOF 或断链会立即停止队列，不发送未经 HCI 验证的
设备取消命令，也不会盲目重发最后一片。此时终态是“设备状态未知”。

Mass 分片为惰性生成，只保留源文件与当前发送窗口，不再同时复制全部 10 MiB 块和分片。

应用专用目录只保存一个可恢复检查点：源路径、大小、MD5、SHA-256、元数据、阶段和已确认片号。
它不含 authkey、会话密钥或文件副本。重新连接后必须重新认证，并重新执行
`MassPrepare`；只有设备给出的可信断点与本地文件完全一致时才可续传。

表盘只有收到 `(4,5)` 完成事件后才发送 `setFace(faceId)`。RPK 在 Mass 完成后
等待 `(20,2)`，解析 `v8s.field4=l8s`，并要求结果包名与当前清单包名一致；状态码
为 0 才宣称成功，设备明确失败进入失败态；缺少状态码或包名的畸形结果保持“状态未知”
且不删除检查点。完成事件监听在传输前建立以避免漏包，但
120 秒设备安装结果超时只在全部 Mass 数据确认后开始计时，大文件传输时间不计入该超时。

Windows 与 Android 的 RFCOMM 读取循环均使用连接代次隔离：旧 socket 延迟到达的
字节或 EOF 不得关闭、污染新连接。Android 首次连接等待系统 bond 完成，既有 bond
直接复用，不自动解绑；Android 6–11 请求扫描所需的位置权限，Android 12+ 请求附近
设备扫描/连接权限。
